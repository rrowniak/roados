# TASK_UI_DEMO_02.1: Demo Icon Subsystem — One White Master per Size, Color as a Shader Tint, Composable with Button

## Goal

Render `ui/src/ui_demo/assets/icons/airbag-svgrepo-com.svg` on the demo page at a caller-chosen size and color: **one baked white master PNG per size** loaded through `Renderer::load_texture`, with the **color applied at runtime as a shader tint** (`TASK_UI_PRIM_44`'s tinted-image pipeline: `DrawCommand::Image::tint`, `Painter::tinted_image`, per-vertex tint multiply). No per-color PNG variants. Composed as a sibling node beside a `Button` (e.g. one dock slot's glyph cell). No new workspace dependency, no runtime SVG parsing. **Hard dependency on `TASK_UI_PRIM_44` requirements 2–6** (tint pipeline + `Icon` widget): this task consumes them and does not re-specify them — if 44 has not landed, this task is blocked, not degraded (without the shader multiply there is no runtime tint to consume). This is the demo-side half of `TASK_UI_DEMO_02`'s placeholder dock glyphs (`chrome.rs` `DOCK_GLYPHS`).

## Context

**Color is a shader multiply, so one master serves every color.** Task 44 adds `tint: Color` to `DrawCommand::Image` (documented as a premultiplied modulate, deliberately **not** in `BatchKey`, so differently-colored icons sharing one texture stay one draw call), threads it per-vertex (`IMAGE_TINT_OFFSET = 40`, attribute 6), and ends the image fragment shader in `frag_color = vec4(texel.rgb * v_tint.rgb * opacity, texel.a * v_tint.a * opacity)`. The baked master is therefore **white, opaque glyph on transparent background**; the caller-chosen color arrives as the tint. Neutral tint is opaque white (`paint::untinted()`), which leaves non-icon images unchanged. Per-color PNGs are refused, not merely unneeded: requirement 1's guard fails a bake set holding two colors of one glyph.

**This SVG is fill-based, not Lucide-style.** Root carries `fill="#000000"`, paths carry no stroke, `viewBox="0 0 512.003 512.003"`. Task 39's `*{color:…}` stylesheet rule tints `stroke="currentColor"` sets and does nothing to this file; the baker must use a **`{fill:…}` rule instead**, and the input guard must assert `fill` (not `stroke`) on the root. Reusing task 39's rule verbatim yields a black icon on the dark theme with exit status 0.

**No mipmaps, no DPI.** `MIN_FILTER` is `GL_LINEAR`, `generate_mipmap` is never called, 1 asset px = 1 window px (task 39 § *The engine constraints*). "Dynamic size" means **baked at the exact on-screen pixel size** and drawn 1:1 (`ImageFit::Fill` on matching shapes is the identity); the widget never scales, a smaller cell crops.

**`Button` takes text, not an icon** (`Button::new(&mut nodes, &str)`; no icon slot). Composition therefore means a **sibling `Image` node in the same row container**, not a `Button` change. A `Button::icon` API is future work owned by `TASK_UI_PRIM_44`, not this task.

## Requirements

1. **Baked bytes, committed: one white master per size.** Bake the airbag SVG with `resvg` (absolute path `~/.cargo/bin/resvg`; `~/.cargo/bin` is not on `PATH`) at the sizes in requirement 3, stylesheet `{fill:#ffffff}`. Commit the PNGs beside the SVG under `ui/src/ui_demo/assets/icons/` (e.g. `airbag_<size>.png`); the SVG stays. Record the exact commands in `tools/asset-pipeline/README.md` (or the module doc if that file is absent). If `MANIFEST.sha256` / `check_assets.py` covers `assets/`, amend the manifest so the guard stays green. The bake asserts three pixel facts: the background stays transparent (the SVG holds no background element — three paths, no `<rect>` — so corner pixels must read alpha 0), the glyph is white (mean of non-transparent pixels ≈ 255, never 0 — a missing stylesheet bakes black with exit status 0), and anti-aliasing survived (at least one pixel with `0 < alpha < 255`; resvg stores straight RGBA and the bake must not threshold it — `texture.rs` `decode` premultiplies on load and the blend is `ONE, ONE_MINUS_SRC_ALPHA`, so intermediate alpha composites to soft edges, and a binarized master would still draw, just jaggy). Caller-side tint colors are premultiplied-by-contract (`Color::new` does not premultiply); opaque tints are unaffected.
2. **`ui/src/ui_demo/src/icons.rs`, new, `mod icons;` beside `mod chrome;`.** Module doc states: fill-based source and its `{fill}` rule, bake-at-size rationale with pointer to task 39, white-master-plus-tint rationale with pointer to task 44, 1:1 draw rule, sibling-composition with `Button`.
3. **`pub struct IconSpec { pub size_px: u32, pub color: Color }` + `#[must_use] pub fn baked_file(size_px: u32) -> &'static str`.** The file table is keyed by size only (two sizes, e.g. 24 and 48; unknown size maps to the nearest baked file, documented); `color` never touches the filesystem — it becomes the `Icon` tint at paint time. `size_px` in `1..=512` (`ATLAS_MAX_IMAGE`); both dimensions equal. Tests `baked_file_resolves_every_baked_size`, `unknown_size_maps_to_nearest_baked_file`; `icon_color_never_selects_a_file` asserts two specs differing only in color resolve to the same file.
4. **`#[must_use] fn destination(rect: Rect, side: f32) -> Rect`** — centred `side` square ∩ `rect` (task 44's `centred_square` shape, demo-local). `pub fn paint(spec: &IconSpec, rect: Rect) -> Vec<DrawCommand>` drives task 44's `Icon` (or `Painter::tinted_image` directly): exactly one tinted-image command with `ImageFit::Fill` and full UV, `tint = spec.color`, `opacity` the existing `Image::opacity`/`shown_opacity` scalar (clamped `0.0..=1.0` by the pipeline); empty intersection records nothing. Tests `the_icon_is_centred_in_its_rect`, `every_icon_records_a_rect_inside_the_rect_it_was_given`, `an_icon_paints_exactly_one_tinted_image_command`, `the_icon_carries_the_tint_it_was_given`, `an_icon_in_a_translucent_state_records_the_opacity_it_holds`.
5. **One composition site in `chrome.rs` (or `main.rs` beside the dock):** a row container holding the existing `Button` plus the icon `Image` node as siblings; `Button` untouched (still text label, no `set_palette` added). One `page_members` row (`Page::Demo`, `focusable: false`), one paint arm calling `icons::paint` after the map arm and before/with the chrome arm. Tests `the_icon_is_on_the_demo_page_and_on_no_other_page`, `the_demo_page_draws_the_icon_and_the_gallery_pages_do_not`.
6. **Theme following through the tint property, not file selection.** The demo binds the icon's tint to the theme token property (`Property::bind` over `theme.property(token)`, task 44's `a_theme_switch_reaches_the_icon` shape): `a_theme_switch_reaches_the_icon` proves the tint is dark-ink, strictly between mid-transition, then exactly light-ink — with no clock in `icons.rs`. No file switch, no second PNG set.
7. **Suite and hygiene.** `ui/Cargo.toml` / `ui/Cargo.lock` unchanged (approved direct deps `sdl3 0.20`, `glow 0.18`, `freetype-rs 0.38`); no file under `ui/src/ui_core/src/`; no `unsafe`, `unwrap()`, `expect()`, `panic!`, `todo!`; no display/network/filesystem/wall-clock test (all tests use `IconSpec` values and rect math, never the PNG bytes).
